# AGENTS.md — Memory Vault (LLM Wiki)

This vault is a personal knowledge base maintained by LLM agents using the
**LLM Wiki** pattern. Raw sources are ingested once, then compiled into a
persistent, interlinked `Wiki/` that compounds over time. The agent owns the wiki;
the human sources material, directs the analysis, and asks questions.

This file is the **authoritative schema**. Read it first, every session. Detail
lives in `Schema/` — follow the links rather than guessing.

## Non-negotiable rules

1. **`Raw/Sources/` is source material, not compiled notes.** Treat it as immutable
   provenance. Never edit, rewrite, or delete raw files after capture, and never
   store synthesized/reusable knowledge there. **`Raw/**` must not use `[[wikilinks]]`**
   (plain text / URLs only) — Raw nodes must not appear as edges in the Obsidian graph.
   The global graph filter is `-path:Raw` (see `.obsidian/graph.json`).
2. **Write reusable knowledge only under `Wiki/`.** Any summary, synthesis, comparison,
   or connection that should be reused belongs in `Wiki/` — never in `Raw/`, never only
   in chat history. The graph is Wiki-only.
3. **Keep provenance in frontmatter only.** Every `Wiki/` note lists supporting
   raw paths under `sources` (YAML) with matching `source_count`. A note with no
   raw source is a bug (a pure index/log note may legitimately be empty). **Do not**
   put `Raw/` paths in the note body (`## Sources`, prose, or backticks) — readers
   stay in the wiki graph; agents use frontmatter / catalog for provenance.
4. **Search `Wiki/catalog.jsonl` before opening broad Raw context.** Resolve the
   relevant pages from the catalog first; only then read the specific `Raw/` files
   cited by those pages' frontmatter. Do not bulk-scan `Raw/` to answer a question.
5. **Run build, lint, and source checks before commits.** Regenerate the catalog and
   index (build), run the lint checklist, and verify every cited source exists. See
   [`Schema/workflow-examples.md`](Schema/workflow-examples.md) → "Pre-commit checks".
6. **Do not invent citations or create unsupported claims.** If the corpus does not
   support a statement, say so. Never fabricate a source, quote, author, or page.

## Mental model

```
Raw/Sources/   →   Wiki/                →   filed answers
immutable          LLM-compiled,            query results filed
source material     interlinked             back as new pages
```

## Project knowledge

Knowledge about the projects I work on is stored here — the vault is the source of
truth, not per-project `.context/` folders. Project context lives under
`Raw/Projects/<project>/` (raw) and `Wiki/Projects/<project>/` (compiled). The
The `context-curator` Cursor subagent (user config `~/.cursor/agents/`, not this
repo) writes raw notes over MCP (`stage_note`); a repo may still carry a local
`.context/packs/` bundle for handoff, but no `.context/` tree.

- **`Raw/Projects/<project>/`** — a **refreshable** mirror of project context:
  `INDEX.md`, optional **components** (`vue-project/`, `auth-service/`, …) each with
  their own `domains/`, `entities/`, `layers/`, `contracts/`, `tech/`, plus
  project-level or component-level notes. MCP `stage_note(..., component=)` writes
  into a component; omit `component` for project-root kinds. `packs/` are derived
  and ignored. Unlike `Raw/Sources/` (strictly write-once), notes here may
  be **overwritten** (e.g. by `vault_stage_note`). Each file carries the source
  frontmatter plus `project:` and `kind:` (a canonical kind such as
  `index | context | domain | entity | layer | contract | tech | module | artifact`,
  or a folder name).
- **`Wiki/Projects/<project>/`** — compiled notes: an anchor `<project>.md`
  (`kind: project`) plus `domains/`, `entities/`, `layers/`, `contracts/`, `tech/`
  (and any project-specific) children. Every project note carries `project: <name>` and `scope: project | shared`;
  a `project:`-aware lint rule lets it live in the nested folder regardless of `tags[0]`.
- **Compile:** `python3 scripts/wiki_tool.py project-ingest`, or the MCP tool
  `project_ingest` (capture = prepend raw frontmatter; compile = write `Wiki/Projects/`
  and rebuild the catalog). Idempotent; re-runs refresh notes.
  Actualization is explicit — keep a `supersedes` chain plus a `log.md` entry.
- **Shared vs project:** reusable concepts/entities are promoted to global
  `Wiki/Concepts` / `Wiki/Entities` (`scope: shared`) during maintenance; everything
  else stays project-scoped. Within/across projects, note titles are disambiguated as
  `Title (project)` to keep `[[wikilinks]]` unique.
- **Reading scope:** start from the project anchor and follow `[[wikilinks]]` 1–2 hops.

## Tooling

`scripts/wiki_tool.py` (stdlib only) is the canonical implementation of build,
lint, source checks, catalog search, and logging:

```bash
python3 scripts/wiki_tool.py doctor            # non-mutating health check
python3 scripts/wiki_tool.py build             # catalog + index files
python3 scripts/wiki_tool.py lint              # validate compiled notes
python3 scripts/wiki_tool.py source-scan --update --accept-covered
python3 scripts/wiki_tool.py source-lint       # source frontmatter + coverage
python3 scripts/wiki_tool.py project-ingest    # Raw/Projects -> Wiki/Projects (capture + compile)
python3 scripts/wiki_tool.py search-catalog --query "text"
python3 scripts/wiki_tool.py log --title "ingest: X" --details "+1 note"
```

Agents read the vault (and hand new project knowledge back) over MCP via
`scripts/vault_mcp.py` — read tools (`search_catalog`, `read_note`, `read_project`,
`list_recent`) plus write tools (`stage_note` writes/overwrites a `Raw/Projects/` note —
optionally under a `component` module folder with its own `domains/`/`layers/`/… —
`project_ingest` compiles it into `Wiki/Projects/` and rebuilds the catalog, `log`
appends to `Wiki/log.md`); all writes take a global lock. The periodic job
`scripts/maintain_vault.py` runs the toolchain (incl. `project-ingest`) then the
Cursor Agent CLI (`agent -p --force --trust`; optional `--agent opencode` fallback)
every 3h.

Git hooks: `sh scripts/install_hooks.sh` sets `core.hooksPath=.githooks`; the
pre-commit hook runs `build`, `lint`, and `source-lint`. Before publishing,
`python3 scripts/audit_public.py` fails on secrets, machine-local paths, private
keys, and plugin/cache state.

## Frontmatter

Every `Raw/Sources/` source note and every `Wiki/` compiled note carries YAML
frontmatter. Contract: [`Schema/frontmatter-schema.md`](Schema/frontmatter-schema.md).

Compiled note:

```yaml
---
tags:
  - "concept"          # first tag ∈ topic | concept | entity | project | log
topics: []
status: seed           # seed | growing | mature | stale
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: []            # Raw/Sources/ or Raw/Projects/ paths
source_count: 0        # MUST equal len(sources)
aliases: []
project: ""            # optional; project-scoped note (lives under Wiki/Projects/<project>/)
scope: ""              # optional: project | shared
supersedes: []         # optional; prior note(s) this one actualizes
---
```

Source note:

```yaml
---
Title: ""
Author: ""
Reference: ""
ContentType:
  - "markdown"
Created: YYYY-MM-DD
Processed: false
tags:
  - "source"
---
```

## Naming

See [`Schema/naming-conventions.md`](Schema/naming-conventions.md). Highlights:
raw files `Raw/Sources/<type>-<kebab-topic>.md` (e.g. `article-llm-wiki-pattern.md`);
wiki pages **Title Case** (`LLM Wiki Pattern.md`); all internal references use
`[[Wikilinks]]`; dates ISO `YYYY-MM-DD`.

## Page shape

```
# {Title}
{2–3 sentence summary}

## Key Concepts
## Details
## Connections   ← mandatory, ≥1 [[wikilink]]
```

Provenance lives in frontmatter `sources:` / `source_count` only — never a body
`## Sources` block pointing at `Raw/`.

Templates: [`Schema/_templates/`](Schema/_templates/) — `source-note.md`,
`topic-note.md`, `concept-note.md`, `entity-note.md`, `project-note.md`, `log-note.md`,
`project-source-note.md`, `project-anchor-note.md`.

## Quality rules

- **One page per concept**, not per source.
- **Connections mandatory** — every page links to ≥1 other page. No orphans.
- **Every page is sourced** — frontmatter `sources:` resolves to real files under `Raw/`.
- **No Raw paths in Wiki bodies** — do not cite `Raw/Sources/` or `Raw/Projects/` in prose.
- **Preserve nuance** — flag contradictions, never silently pick a side.
- **Never delete raw files.** Even after compilation they remain the source of truth.
- **Quality over quantity** — hold a thin source rather than write a stub you cannot source.

## Lint

Routine health check: [`Schema/lint-checklist.md`](Schema/lint-checklist.md).
Broken structure beats stale content — report the most structural problem first.

## Logs

`Wiki/log.md` is append-only, prefix-parseable
(`grep "^## \[" log.md | tail -5`). Written by `wiki_tool.py log`:

```
## [YYYY-MM-DD] ingest: Source Title
- +1 note
## [YYYY-MM-DD] query: question-slug
## [YYYY-MM-DD] lint: N findings (top issue)
```
