# Command reference

Tooling for the vault. Standard library only.

| Tool | Purpose |
|---|---|
| `scripts/wiki_tool.py` | Build, lint, catalog, manifest, search, log. |
| `scripts/audit_public.py` | Fail on secrets / local paths / keys / cache state. |
| `scripts/install_hooks.sh` | Point git at `.githooks/`. |
| `.githooks/pre-commit` | Pre-commit gate: build + lint + source-lint. |

The vault root is the parent of `scripts/` (override with `$WIKI_ROOT`).

---

## `wiki_tool.py`

```bash
python3 scripts/wiki_tool.py <command> [options]
```

### `doctor`
Non-mutating health check. Verifies required folders, Python version (>= 3.8),
catalog and manifest readability, and prints note/source counts plus coverage.
Exit `1` on hard errors, `0` otherwise (warnings allowed).

### `build`
Regenerates derived artifacts from note frontmatter:
- `Wiki/catalog.jsonl`
- `Wiki/index.md` (grouped by kind)
- per-folder indexes: `Wiki/Topics/index.md`, `…/Concepts/index.md`, `…/Entities/index.md`, `…/Projects/index.md`, `…/Logs/index.md`

Notes without parseable frontmatter are skipped (reported on stderr). Generated
files are never treated as notes. Project notes (`project:` set) are grouped under
`Wiki/Projects/index.md` and a per-project `Wiki/Projects/<project>/index.md`.

### `lint`
Validates compiled `Wiki/` notes. Errors (exit `1`):
- missing/unparseable frontmatter
- `tags[0]` not in `topic | concept | entity | project | log`
- tag does not match the containing folder (relaxed for notes with `project:` — they
  must live under `Wiki/Projects/<project>/` and be `project` | `concept` | `entity`)
- `source_count` missing, not an integer, or `!= len(sources)`
- a `sources` entry not under `Raw/Sources/`+`Raw/Projects/` or not present on disk
- missing / malformed `updated` (`YYYY-MM-DD`); invalid `scope`

Warnings: missing `## Connections` section, a Connections section with no `[[wikilink]]`,
a duplicate `title`/`alias` across notes; missing catalog.

### `source-scan`
Lists `Raw/Sources/` and `Raw/Projects/` source files (`packs/` excluded) and their
coverage (dry run).

```bash
python3 scripts/wiki_tool.py source-scan --update
python3 scripts/wiki_tool.py source-scan --update --accept-covered
```

- `--update` writes `Schema/source-manifest.jsonl`.
- `--accept-covered` additionally marks sources that are covered by compiled Wiki
  notes as processed (manifest `processed: true` and source frontmatter `Processed: true`).

### `source-lint`
Validates Raw source frontmatter and coverage. Errors (exit `1`):
- missing required keys `Title`, `Reference`, `Created`, `Processed`, `tags`
- `tags` does not include `"source"`
- a project source lacking `project` or a valid `kind`
- a source marked processed (frontmatter `Processed: true` or manifest
  `processed: true`) with **no** Wiki coverage

Warnings: covered but not processed; absent from the manifest.

### `source-delta`
Shows `Raw/Sources/` + `Raw/Projects/` files not represented in the manifest (and
stale manifest entries).

### `source-coverage`
Shows which Raw sources are covered by compiled Wiki notes, and by which notes.

### `project-ingest`
Captures `Raw/Projects/<project>/**` — prepends the source frontmatter (adding
`project:` and `kind:`; `packs/` are skipped) — then compiles it into
`Wiki/Projects/<project>/**`: an anchor `<project>.md` (`kind: project`) plus
`domains/`, `entities/`, `layers/`, `contracts/`, `tech/`, `modules/`, `artifacts/`
notes (project-specific subfolders compile as `concept`). Idempotent; a title
that collides across projects (or with a global note) is suffixed `Title (project)`.

```bash
python3 scripts/wiki_tool.py project-ingest
python3 scripts/wiki_tool.py project-ingest --project ui-session-marking
python3 scripts/wiki_tool.py project-ingest --no-compile      # capture only
python3 scripts/wiki_tool.py project-ingest --dry-run
```

### `search-catalog`
```bash
python3 scripts/wiki_tool.py search-catalog --query "incremental"
```
Case-insensitive substring search over `title`, `tag`, `topics`, `sources`, `path`
in `Wiki/catalog.jsonl`. Run this **before** reading broad `Raw/` context.

### `log`
```bash
python3 scripts/wiki_tool.py log --title "ingest: LLM Wiki Pattern" --details "1 note"
```
Appends `## [YYYY-MM-DD] <title>` (+ optional `- <details>`) to `Wiki/log.md`.

## Contracts

### `Wiki/catalog.jsonl` — one object per compiled Wiki note
```json
{"path":"Wiki/Concepts/example.md","title":"Example","tag":"concept","topics":[],"project":"","scope":"","sources":[],"updated":"YYYY-MM-DD"}
```
Generated by `build`; fixed field order (`path,title,tag,topics,project,scope,sources,updated`); never hand-edited.

### `Schema/source-manifest.jsonl` — one object per Raw source
```json
{"path":"Raw/Sources/example.md","title":"Example","processed":true,"covered_by":["Wiki/Concepts/example.md"],"updated":"YYYY-MM-DD"}
```
Covers both `Raw/Sources/` and `Raw/Projects/` (projects exclude `packs/`).
Generated by `source-scan --update`; `covered_by` is derived from note `sources`.

## `vault_mcp.py` — MCP server

Minimal Model Context Protocol server (JSON-RPC 2.0 over stdio, stdlib only) so
agents read the vault and hand new knowledge back for compilation. Reads are
unlocked; writes take the global lock `Schema/.vault.lock`.

```jsonc
// opencode MCP config
{ "mcp": { "memory-vault": { "type": "local", "command": ["python", "scripts/vault_mcp.py"] } } }
```

Tools:

| Tool | Purpose |
|---|---|
| `search_catalog(query, project?, limit?)` | search `Wiki/catalog.jsonl` |
| `read_note(path)` | read a `Wiki/` note or `Raw/` file (path relative to vault) |
| `read_project(project)` | anchor note + component list for a project |
| `list_recent(limit?)` | recently updated compiled notes |
| `stage_note(project, kind, name, body, component?)` | write/overwrite a raw note under `Raw/Projects/` (locked). Optional `component` = service/SPA folder (`vue-project`, `auth-service`); kinds then land in `<component>/domains/` etc. |
| `log(title, details?)` | append to `Wiki/log.md` (locked) |

`stage_note` only **captures**; run `project-ingest`/`build` (or the periodic job) to
compile. Agents must not edit `Wiki/` directly.

## `audit_public.py`

```bash
python3 scripts/audit_public.py
python3 scripts/audit_public.py --allow ".obsidian/**" --quiet
```

Fails (exit `1`) on:
- **secrets** — `api_key`/`token`/`password`/`secret` assignments, bearer tokens,
  `sk-…`, `ghp_…`, `AKIA…`
- **machine-local paths** — Windows drive profiles (`%USERPROFILE%`), macOS `/Users/*`, Linux `/home/*`
- **private keys** — `-----BEGIN … PRIVATE KEY-----`
- **plugin/cache state** — `node_modules`, `__pycache__`, `.obsidian`, `.venv`,
  `.pytest_cache`, `.coverage`, `.env`, `.DS_Store`, `*.pyc`, …

Derived/cache paths are ignored by default (`.git`, `.obsidian`, `.runs`, cache
dirs, and `Raw/Projects/*/packs/**`). `Schema/audit-allow.txt` holds reviewed
exceptions (one fnmatch glob per line, `#` comments); `--allow GLOB` adds one-off
exemptions.

## Git hooks

```bash
sh scripts/install_hooks.sh      # sets core.hooksPath=.githooks
```

`.githooks/pre-commit` runs:
```bash
python3 scripts/wiki_tool.py build
python3 scripts/wiki_tool.py lint
python3 scripts/wiki_tool.py source-lint
```
It refuses to commit a stale catalog, invalid compiled notes, or sources marked
processed without coverage.
