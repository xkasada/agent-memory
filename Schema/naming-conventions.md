# Naming conventions

## Source notes — `Raw/Sources/`

Format: `<kind>-<kebab-case-topic>.md`. Use the source's topic, not the URL slug.

| Prefix | Use for |
|---|---|
| `article-` | Web article, blog post, news |
| `idea-` | Your own idea or proposal |
| `highlights-` | Book/article highlights |
| `braindump-` | Unstructured thinking |
| `note-` | Quick reference (recipe, command, fact) |
| `resource-` | Non-text source (PDF, video, podcast, image) |
| `tweet-` | Single X post or thread |
| `call-` | Call / meeting transcript |
| `meeting-` | Your own meeting notes (not auto-transcripts) |
| `person-` | Contact / profile note (CRM-lite) |
| `company-` | Organization profile |

Examples:

```
Raw/Sources/article-llm-wiki-pattern.md
Raw/Sources/highlights-thinking-fast-and-slow.md
Raw/Sources/call-2026-09-22-acme-discovery.md
Raw/Sources/person-jane-doe.md
```

Source notes carry frontmatter (`Title`, `Author`, `Reference`, `ContentType`,
`Created`, `Processed`, `tags: ["source"]`) — see
[`frontmatter-schema.md`](frontmatter-schema.md). **Write-once**; never edit/delete.

Attachments live in `Raw/Files/` and are referenced by path from the source body.

## Project source notes — `Raw/Projects/<project>/`

Mirror of a project's `.context/` with identical names/structure:

```
Raw/Projects/<project>/INDEX.md
Raw/Projects/<project>/CONTEXT.md
Raw/Projects/<project>/domains/<domain>/overview.md
Raw/Projects/<project>/entities/<Entity>.md
Raw/Projects/<project>/layers/<layer>.md
Raw/Projects/<project>/contracts/<contract>.md
Raw/Projects/<project>/tech/<file>.md
Raw/Projects/<project>/modules/<file>.md
Raw/Projects/<project>/artifacts/<file>.md
```

The sub-kind set is open: any project subfolder maps to a `kind` named after it
(known: `domains|entities|layers|contracts|tech|modules|artifacts`; `entities` →
`entity`, the rest → `concept`). `packs/` are derived — not captured. Capture prepends source frontmatter plus
`project:` and `kind:` (see [`frontmatter-schema.md`](frontmatter-schema.md)).

## Compiled notes — `Wiki/**`

- **Title Case**, descriptive, human-readable: `LLM Wiki Pattern.md`,
  `Incremental Compilation.md`, `Obsidian.md`.
- **One note per concept** — never per source. Merge into an existing note when the
  topic overlaps; create a new note only when nothing fits.
- The filename stem **equals** the note's H1 title.
- The first `tags` entry determines the folder:

| `tags[0]` | Folder |
|---|---|
| `topic` | `Wiki/Topics/` |
| `concept` | `Wiki/Concepts/` |
| `entity` | `Wiki/Entities/` |
| `project` | `Wiki/Projects/` |
| `log` | `Wiki/Logs/` |

- **Project notes** carry `project: <name>` and live under
  `Wiki/Projects/<project>/` regardless of `tags[0]` (`project` | `concept` | `entity`):
  an anchor `<project>.md` plus `domains/`, `entities/`, `layers/`, `contracts/`,
  `tech/` (and any project-specific subfolders, e.g. `modules/`, `artifacts/`).
  Globally reused concepts/entities are promoted to `Wiki/Concepts` /
  `Wiki/Entities` with `scope: shared`.
- **Disambiguation.** When a title would collide across projects (or with a global
  note), compile suffixes it as `Title (project)` so `[[wikilinks]]` stay unique.
  `project-ingest` does this automatically.

- **Stable names.** Rename only as a deliberate, logged operation — then fix inbound
  `[[links]]`, the catalog, and the index.

## Templates

Copy from `Schema/_templates/`: `source-note.md`, `topic-note.md`,
`concept-note.md`, `entity-note.md`, `project-note.md`, `log-note.md`,
`project-source-note.md`, `project-anchor-note.md`.

## Wikilinks

- Reference every related note with `[[Note Name]]` (Obsidian style).
- Prefer a link over a bare mention the first time a note name appears.
- The `## Connections` section is **mandatory** and must contain ≥1 link.
- Aliases (frontmatter `aliases:`) resolve to the canonical note title.

## index files

- `Wiki/index.md` plus per-folder `Wiki/<Kind>/index.md` (`Topics`, `Concepts`,
  `Entities`, `Projects`, `Logs`), all generated from note frontmatter by `build`.
- Do not hand-edit; they are overwritten on every build.
- One line per note: `- [[Note Name]] — one-line summary`.

## catalog.jsonl

- One JSON object per compiled note per line; fixed field order for stable diffs.
- Generated, never hand-edited. Path is `Wiki/catalog.jsonl`.
- Searched by `query` (`wiki_tool.py search-catalog`) before any broad `Raw/` reading.

## Sources manifest

- `Schema/source-manifest.jsonl`: one object per Raw source, generated by
  `wiki_tool.py source-scan --update`.

## Logs

- File: `Wiki/log.md`, append-only; written by `wiki_tool.py log`.
- Prefix: `## [YYYY-MM-DD] <title>` with optional `- <details>` lines.
- Compiled `log`-tagged notes live under `Wiki/Logs/`.

## Tags and dates

- Tags: lowercase; the first compiled-note tag is the note kind.
- Dates: ISO `YYYY-MM-DD` everywhere.
- Source filenames: kebab-case, no spaces. Compiled note filenames: Title Case.
